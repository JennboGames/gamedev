# Integration plan

Hand-off from `azure-project-scaffold` to `azure-project-integrate`. Paths are workspace-root relative.

## Backend: Foundation Collector API
- Folder: `api/` (Azure Functions v2, Python 3.11). Venv: `api/.venv` (`pip install -r requirements-dev.txt`).
- Run: `func start` in `api/` (Core Tools and Docker were NOT installed at scaffold time). Port `7071`.
- Test: `pytest` in `api/` (67 tests pass; no external services needed).
- Health: `GET http://localhost:7071/api/health` -> `{ status, services: { database, storage, amazon } }`; `degraded` is 200, `unhealthy` is 503.
- Local emulators: `docker-compose up -d` (Azurite on 10000-10002, PostgreSQL 16 on 5432). Credentials live in root `.env` (gitignored); `api/local.settings.json` mirrors them and sets `AZURE_FUNCTIONS_ENVIRONMENT=Development`.
- Provider selection: only the exact value `Development` selects Azurite + local PostgreSQL; anything else selects managed identity (`AZURE_STORAGE_ACCOUNT`, `AZURE_POSTGRES_HOST/DATABASE/USER`).
- Amazon PA-API (`AMAZON_PAAPI_ACCESS_KEY`, `AMAZON_PAAPI_SECRET_KEY`, `AMAZON_PARTNER_TAG`) is empty locally: credentials are validated lazily, so the app starts, `/health` reports `amazon: false` (degraded), and an Amazon-only `POST /api/searches` returns 500 `CONFIGURATION_ERROR` until they are set. Smoke-test search with a recorded transport or real keys.
- Retailers: Amazon (PA-API), Ulta (public foundation listing + product-page JSON-LD, plain rate-limited HTTP, no credentials) and Sephora (registered but always reports a warning: it answers automated requests with HTTP 403 and is not worked around). A retailer that fails becomes an entry in `warnings`; the search only errors when every selected retailer fails and nothing was found.
- Pinned Amazon products (`PINNED_ASINS`, default `B0GQVP8RLD,B0028P5TOW,B0HC436QM3,B0BFRV3GCS,B00AVUDDC6,B0BNWBT2G2,B078QZDJFB`; empty string disables) are collected on every search, even when Amazon is not selected.

## API routes (prefix `/api`)
| Method | Path | Success | Errors |
|--------|------|---------|--------|
| GET | `/health` | 200 / 503 | |
| POST | `/searches` body `{ query, maxProducts?, retailers? }` (`retailers` is a non-empty subset of `amazon`, `ulta`, `sephora`; default `["amazon"]`) | 201 `{ searchId, products[], warnings[] }` | 400, 422, 500, 502 |
| GET | `/products` | 200 `{ items[] }` | |
| GET | `/products/{id}` | 200 Product | 404, 422 (bad uuid) |
| GET | `/products/{id}/shades` | 200 `{ items[] }` | 404, 422 |
| POST | `/shades/{id}/extract-hex` | 200 Shade | 404, 422, 502 |
| POST | `/color-map` body `{ productIds? }` (optional) | 201 ColorMap | 404, 422 |
| GET | `/color-map` | 200 ColorMap | 404 |
| GET | `/openapi.json` | 200 | |

Error shape: `{ error: { code, message, details? } }`.

## Database (PostgreSQL, no seed data)
- Migration tool: none chosen yet; plain SQL files in `api/migrations/` (currently only `.gitkeep`). Create the schema below. **Do NOT create seed data.**
- Connection env: `DATABASE_URL` (local) / `AZURE_POSTGRES_HOST`, `AZURE_POSTGRES_DATABASE`, `AZURE_POSTGRES_USER` (production, Entra token as password).
- ID values are generated by the app (`uuid4`); use `UUID PRIMARY KEY` without relying on defaults. Timestamps default to `now()`.

| Table | Columns |
|-------|---------|
| `searches` | `id`, `query TEXT NOT NULL`, `created_at` |
| `products` | `id`, `retailer TEXT NOT NULL CHECK IN ('amazon','ulta','sephora')`, `asin TEXT NOT NULL` (the retailer's own product id), `UNIQUE (retailer, asin)` (upsert target), `title NOT NULL`, `brand`, `detail_page_url`, `image_url`, `status CHECK IN ('collected','extracting','partial')`, `search_id` FK `searches` ON DELETE SET NULL, `created_at`, `updated_at` |
| `shades` | `id`, `product_id` FK `products` ON DELETE CASCADE, `asin NOT NULL`, `name NOT NULL`, `swatch_url`, `swatch_blob_name`, `hex CHECK ~ '^#[0-9A-F]{6}$'`, `hue`, `lightness`, `status CHECK IN ('extracted','failed')`, `error`, `created_at`, `updated_at`, `UNIQUE (product_id, asin)` (upsert target) |
| `color_maps` | `id`, `blob_name NOT NULL`, `width INT`, `height INT`, `created_at` |
| `color_map_markers` | `id`, `color_map_id` FK `color_maps` ON DELETE CASCADE, `shade_id` FK `shades` ON DELETE CASCADE, `x`, `y` (double, 0-1), `hex`, `hue`, `lightness` |

`hue` is degrees 0-360, `lightness` is percent 0-100 (use `NUMERIC` or `DOUBLE PRECISION`). `products.sample_hexes` is computed in SQL (`ntile(5)` subquery in `PostgresShadeRepository._PRODUCT_SELECT`); verify it against a real database during smoke testing. Writes spanning tables (`save_search`, `update_shade_extraction`, `save_color_map`) run in one transaction.
- Blob containers (created on demand by the Azurite provider): `swatches`, `colormaps`.

- **API seam to swap**: `web/src/api/index.ts` (`export const api: ApiClient = mockClient;`). Create `web/src/api/client.ts` implementing `ApiClient` from `web/src/api/types.ts` method-for-method and repoint the export:
